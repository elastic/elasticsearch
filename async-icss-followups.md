# Follow-ups for asynchronous index cluster-state application

Review baseline: PR [#145363](https://github.com/elastic/elasticsearch/pull/145363), local merge `6974bbd5b8b7`. The items below come from a read-only code review.

## Shared wait and acknowledgement

- [ ] **Publication acknowledgements.** Use the publication that satisfied acknowledgement to determine the minimum cluster-state version and the required participants for mapping, settings, and index deletion. The three implementations currently read `clusterService.state()` after acknowledgement and can fan out against an unrelated membership change. Share observation across batched tasks while preserving individual deadlines, the separate master-queue timeout, and the no-timeout sentinel. Return unsuccessful publication acknowledgements without another fan-out. Fix the delayed-replica case and remove the existing `RareClusterStateIT` mute. [Publication acknowledgements](server/src/main/java/org/elasticsearch/cluster/service/MasterService.java#L875) · [Test mute](muted-tests.yml#L731)

## APIs that read or act on local index state

Carry the relevant routing or metadata version from the dispatch snapshot. Wait on the receiver before looking up the shard, taking a permit, or opening a reader. Recheck allocation identity after the wait and resume on the existing executor. For cross-cluster requests, use the target cluster’s version and gate new wire fields for transport compatibility.

- [ ] **Search and query-aware search-shards.** Cover can-match, query, DFS, and batched query requests. A stale mapper can rewrite a valid query to `match_none` and silently drop the only matching shard. Propagate the same version requirement through the batched request. [Search service](server/src/main/java/org/elasticsearch/search/SearchService.java#L3143) · [Batched search](server/src/main/java/org/elasticsearch/action/search/SearchQueryThenFetchAsyncAction.java#L864)
- [ ] **Open PIT.** Cover the separate shard-reader open request and its shared can-match phase. During a stateless split, a receiver with older shard-count metadata can reject the open or leave a partial PIT. Wait before acquiring a reader. [Open PIT receiver](server/src/main/java/org/elasticsearch/action/search/TransportOpenPointInTimeAction.java#L626)
- [ ] **`_field_caps`.** Wait before fetching fields or evaluating `index_filter`. Stale results can be accepted as success. Compute the deduplication hash and fields from a consistent mapper and metadata view. [Field capabilities fetcher](server/src/main/java/org/elasticsearch/action/fieldcaps/FieldCapabilitiesFetcher.java#L117)
- [ ] **`_mapping/field`.** Wait before reading `MapperService`. A just-published field can be omitted, and a missing local shard can be flattened into a partial result or 404. The full mapping API reads published metadata directly. [Field mapping receiver](server/src/main/java/org/elasticsearch/action/admin/indices/mapping/get/TransportGetFieldMappingsIndexAction.java#L93)
- [ ] **Document GET and `_mget`.** Cover shard requests and the separate stateless realtime translog RPCs. During a split, a lagging receiver can reject a summary the coordinator already considers current. The coordinator then waits for a routing change that may never arrive. Multi-get can encounter this as an item failure. [GET receiver](server/src/main/java/org/elasticsearch/action/get/TransportGetAction.java#L169) · [Multi-get receiver](server/src/main/java/org/elasticsearch/action/get/TransportShardMultiGetAction.java#L133) · [Routing retry](server/src/main/java/org/elasticsearch/action/support/single/shard/TransportSingleShardAction.java#L322)
- [ ] **Document `_update`.** Wait before the pre-read, script, and update preparation. A `NOOP` returns before the bulk path, and bulk’s wait occurs after preparation even on write paths. Test an old-routed update during stateless handoff. [Update preparation](server/src/main/java/org/elasticsearch/action/update/TransportUpdateAction.java#L250)
- [ ] **`_explain`, `_termvectors`, and `_mtermvectors`.** Apply the shared single-shard wait. Explain can return `matched:false` with a stale mapper, and term vectors can omit a newly mapped field while reporting the document found. Cover the stateless realtime `EnsureDocsSearchable` hop, whose no-op path bypasses replication’s wait. [Explain](server/src/main/java/org/elasticsearch/action/explain/TransportExplainAction.java#L164) · [Term vectors](server/src/main/java/org/elasticsearch/index/termvectors/TermVectorsService.java#L86) · [Ensure docs searchable](x-pack/plugin/stateless/src/main/java/org/elasticsearch/xpack/stateless/action/TransportEnsureDocsSearchableAction.java#L120)
- [ ] **Index-scoped `_analyze` and Painless `_execute`.** Apply the shared wait to index-backed requests. Analyze can fall back to the default analyzer or enforce stale limits. Painless parses its sample document with the live mapper and can omit a newly mapped field. Preserve indexless execution. [Analyze](server/src/main/java/org/elasticsearch/action/admin/indices/analyze/TransportAnalyzeAction.java#L117) · [Painless execute](modules/lang-painless/src/main/java/org/elasticsearch/painless/action/PainlessExecuteAction.java#L638)
- [ ] **`_validate/query` and `_terms_enum`.** Wait before local rewrite, filtering, or reader lookup. A newly published nested path can produce `valid:false` while the receiver’s mapper is stale. Terms enum can drop a shard using a stale filter and return `complete:true` with no terms. Include the wait in the terms-enum deadline and report incomplete results on timeout. [Validate query](server/src/main/java/org/elasticsearch/action/admin/indices/validate/query/TransportValidateQueryAction.java#L252) · [Terms enum](x-pack/plugin/core/src/main/java/org/elasticsearch/xpack/core/termsenum/action/TransportTermsEnumAction.java#L794)
- [ ] **`_reload_search_analyzers` and `_forcemerge`.** Wait once per destination before local lookup, then revalidate the selected copy. Reload can dereference a missing `IndexService` on a newly assigned node. Force merge can silently skip a published `STARTED` copy that is still locally `POST_RECOVERY`. Preserve genuine unavailability and the existing operation executors. [Reload analyzers](server/src/main/java/org/elasticsearch/action/admin/indices/analyze/TransportReloadAnalyzersAction.java#L132) · [Force merge](server/src/main/java/org/elasticsearch/action/admin/indices/forcemerge/TransportForceMergeAction.java#L95)
- [ ] **Transform checkpoint.** Cover local and remote node execution. The coordinator includes assigned initializing primaries, so a lagging receiver can fail the checkpoint before the shard is created. Derive checkpoint array widths from a consistent routing snapshot or detect topology changes and retry. Mixed widths during an in-place split can break the merge. Filtered checkpoints also depend on the query-aware search-shards fix. [Checkpoint receiver](x-pack/plugin/transform/src/main/java/org/elasticsearch/xpack/transform/action/TransportGetCheckpointNodeAction.java#L90) · [Checkpoint merge](x-pack/plugin/transform/src/main/java/org/elasticsearch/xpack/transform/action/TransportGetCheckpointAction.java#L656)

## Mutation and recovery paths

- [ ] **PUT mapping, PUT settings, and DELETE index.** The mapping no-op path can acknowledge based on published metadata while an earlier mapping application is pending. Apply the same positive-acknowledgement policy to repeated settings updates and overlapping deletions of the same index UUID. Keep settings acknowledgement separate from replacement shard recovery. Keep index-delete acknowledgement separate from eventual resource closure and disk cleanup. [Mapping no-op](server/src/main/java/org/elasticsearch/cluster/metadata/MetadataMappingService.java#L486) · [Settings](server/src/main/java/org/elasticsearch/cluster/metadata/MetadataUpdateSettingsService.java#L431) · [Index deletion](server/src/main/java/org/elasticsearch/cluster/metadata/MetadataDeleteIndexService.java#L104)
- [ ] **`_aliases`.** Validate filtered aliases against the master task’s metadata snapshot. A live `IndexService` can still have an older mapper, causing a valid nested filter to fail. Use a matching or detached validation context so the master task can proceed independently of async application. Alias `remove_index` currently bypasses the index DELETE wait. Its acknowledgement contract is listed below. [Alias validation](server/src/main/java/org/elasticsearch/cluster/metadata/MetadataIndexAliasesService.java#L237) · [Index removal](server/src/main/java/org/elasticsearch/cluster/metadata/MetadataIndexAliasesService.java#L109)
- [ ] **Primary and replica replication, including bulk.** Bind existing pre-permit waits to the publication required by routing, relocation, or split delegation. Preserve executor and force-execution policy and account for cancellation and indexing pressure. Replica mapping retry must recognize a mapping already published but still queued locally. The primary bulk mapping wait needs the remaining request budget. Index block verification benefits from the bounded wait through the same replication handlers. [Replication handlers](server/src/main/java/org/elasticsearch/action/support/replication/TransportReplicationAction.java#L434) · [Replica retry](server/src/main/java/org/elasticsearch/action/support/replication/TransportReplicationAction.java#L828) · [Bulk mapping wait](server/src/main/java/org/elasticsearch/action/bulk/TransportShardBulkAction.java#L276)
- [ ] **Peer recovery translog replay.** On a missing-mapping retry, check current published metadata before subscribing for another publication. Wait for the qualifying local application and reacquire the recovery reference before retrying. Today, releasing the applier can leave replay stuck until an unrelated publication or recovery timeout. [Translog replay](server/src/main/java/org/elasticsearch/indices/recovery/PeerRecoveryTargetService.java#L582)
- [ ] **Stateless split start and handoff.** Drive observer predicates from the published routing for the matching allocation, then wait and revalidate the local shard. Predicates that inspect local `STARTED` or `relocating` state can miss the only publication that would wake them. Make handoff completion enforce the new routing before old-routed writes can proceed, while checking for a permit/application dependency cycle. Before deleting unowned documents, require readiness from each still-assigned search copy or recheck routing and establish that it no longer needs to participate. The wait action currently drops nodes disconnected at dispatch, so the cleanup caller can see success without checking such a copy. [Cleanup wait](x-pack/plugin/stateless/src/main/java/org/elasticsearch/xpack/stateless/reshard/SplitSourceService.java#L1214) · [Split source monitor](x-pack/plugin/stateless/src/main/java/org/elasticsearch/xpack/stateless/reshard/SplitSourceService.java#L1035) · [Handoff completion](x-pack/plugin/stateless/src/main/java/org/elasticsearch/xpack/stateless/reshard/SplitSourceService.java#L544)
- [ ] **Stateless commit notification, recovery commit registration, and unpromotable refresh.** Make these waits allocation-aware. Notification can reach an assigned copy before its `IndexShard` exists. Registration already carries a version but checks ordinary application before the local lookup. Refresh can bind to a retiring copy by shard ID, even though success for a genuinely uncreated copy is intentional. Preserve existing engine, commit-generation, and obsolete-copy handling. [Commit notification](x-pack/plugin/stateless/src/main/java/org/elasticsearch/xpack/stateless/action/TransportNewCommitNotificationAction.java#L105) · [Recovery registration](x-pack/plugin/stateless/src/main/java/org/elasticsearch/xpack/stateless/recovery/TransportRegisterCommitForRecoveryAction.java#L63) · [Refresh receiver](server/src/main/java/org/elasticsearch/action/admin/indices/refresh/TransportUnpromotableShardRefreshAction.java#L128)

## Readiness contract decisions

- [ ] **`_cluster/state?wait_for_async_applied=true`.** Keep returning the qualifying snapshot. Give both phases one deadline, parent the wait to the cancellable request, and define timeout behavior. Preserve the current tolerance for transport disconnects unless the API explicitly promises readiness on every selected node. Decide whether the option covers all data nodes or only affected nodes. Document it in the REST spec if it is public. [Cluster state action](server/src/main/java/org/elasticsearch/action/admin/cluster/state/TransportClusterStateAction.java#L109)
- [ ] **`_cluster/health`, `_cluster/reroute`, and `_recovery`.** Keep ordinary routing responses responsive. If callers need stronger readiness, add a bounded opt-in or put the wait on the consumer. For example, `_recovery` immediately after reroute can omit the new destination before its local shard is installed. A caller waiting for the source to vacate may need actual shard closure. [Health predicates](server/src/main/java/org/elasticsearch/action/admin/cluster/health/TransportClusterHealthAction.java#L391) · [Reroute regression](x-pack/plugin/stateless/src/internalClusterTest/java/org/elasticsearch/xpack/stateless/RerouteIT.java#L206) · [Recovery receiver](server/src/main/java/org/elasticsearch/action/admin/indices/recovery/TransportRecoveryAction.java#L122)
- [ ] **`_close`, data-stream DELETE, and alias `remove_index`.** Decide whether positive acknowledgement should guarantee that former holders removed the live index service. For close, decide separately whether it must invalidate existing scroll or PIT readers, which can require waiting for resource closure or enforcing the fence on the reader path. Data-stream DELETE needs an explicit budget if it adopts a post-publication wait. [Close completion](server/src/main/java/org/elasticsearch/cluster/metadata/MetadataIndexStateService.java#L253) · [Data-stream deletion](modules/data-streams/src/main/java/org/elasticsearch/datastreams/action/TransportDeleteDataStreamAction.java#L100)
- [ ] **`_open`, create, auto-create, rollover, resize, and restore.** Decide whether any caller needs local `STARTED` or primary-mode readiness beyond the existing active-routing or restore-completion guarantee. Prefer fixing receivers that need it. If an explicit readiness option is added, wait only for the copies that satisfy the requested count and preserve `wait_for_active_shards=0`. [Active-shard observer](server/src/main/java/org/elasticsearch/action/support/ActiveShardsObserver.java#L46) · [Restore completion](server/src/main/java/org/elasticsearch/action/admin/cluster/snapshots/restore/TransportRestoreSnapshotAction.java#L81)

## Regression tests

Publish N, pause only the destination’s index-state application, issue the action, and release the pause **without publishing another state**. Also cover a batch that coalesces N into N+1, a newer batch submitted after the wait subscribes, cancellation and timeout, allocation replacement, and mixed-version peers. Gate shard closure or recovery separately wherever the API promises that stronger condition.

* Clusters that store snapshots on storage which is not fully compatible with AWS S3, can fail to [verify respository](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-snapshot-verify-repository) or [delete a snapshot](https://www.elastic.co/docs/deploy-manage/tools/snapshot-and-restore/create-snapshots#delete-snapshot), with failure `Missing required header for this request: Content-MD5` on `DeleteObjects`, after upgrading to Elasticsearch 9.5.0 or 8.19.17, or later. 

  Amazon S3 and third-party storage products that are fully compatible with AWS S3 are not impacted. Review [S3-compatible services](docs-content://deploy-manage/tools/snapshot-and-restore/s3-repository.md#repository-s3-compatible-services) for further Elastic guidance about third-party S3-compatible services.

  As a workaround, set [`s3.client.CLIENT_NAME.legacy_content_md5`](/reference/elasticsearch/configuration-reference/s3-repository-settings.md) to `true` for the affected client. The setting is included and available starting in Elasticsearch 9.5.6, 9.6.0, and 8.19.24. It defaults to `false`, so setting it to `true` explicitly is required. Review [our KB article](https://ela.st/s3-missing-content-md5-header) for more guidance about the workaround.

* Clusters that store snapshots on storage which is not fully compatible with AWS S3, can fail to [analyze respository](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-snapshot-repository-analyze) or [create a snapshot](https://www.elastic.co/docs/deploy-manage/tools/snapshot-and-restore/create-snapshots#manually-create-snapshot), with failure, such as `The Content-SHA256 you specified did not match what we received` or `The provided 'x-amz-content-sha256' header does not match what was computed`, after upgrading to Elasticsearch 8.19.17 or 9.5.0, or later.

  Amazon S3 and third-party storage products that are fully compatible with AWS S3 are not impacted. Review [S3-compatible services](docs-content://deploy-manage/tools/snapshot-and-restore/s3-repository.md#repository-s3-compatible-services) for further Elastic guidance about third-party S3-compatible services.

  As a workaround, before Elasticsearch version 9.5.8, 9.6.1, and 8.19.26, set the environment variable `AWS_REQUEST_CHECKSUM_CALCULATION=when_required` on every Elasticsearch node that uses the repository, or set the JVM system property `-Daws.requestChecksumCalculation=when_required`. From Elasticsearch version 9.5.8, 9.6.1, and 8.19.26 and onwards when available, the environment variable and the system property have no effect on S3 repositories. Set [`s3.client.CLIENT_NAME.unsafely_omit_request_body_checksums`](https://www.elastic.co/docs/reference/elasticsearch/configuration-reference/s3-repository-settings#repository-s3-client-settings) to `true` for the affected client. The setting is included and available starting in those versions. It defaults to `false`, so setting it to `true` explicitly is required. Without the setting, snapshot creation fails again. Review [our KB article](https://ela.st/s3-missing-content-sha256-header) for more guidance.
